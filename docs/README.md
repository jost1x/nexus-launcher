# Documentación

Documentación transversal del diseño, desarrollo, hardware, RPC y roadmap. Los documentos deben describir el estado real del repositorio y separar claramente decisiones pendientes de hechos verificados.

## Documentos previstos

- `architecture.md`: procesos, responsabilidades y límites.
- `development.md`: dependencias y flujo local de desarrollo.
- `hardware.md`: dispositivos, interfaces y capacidades verificadas.
- `rpc.md`: transporte, contratos, errores y compatibilidad.
- `roadmap.md`: fases, criterios de aceptación y estado.

## Fases

- Fase 0: documentar arquitectura, desarrollo y roadmap inicial.
- Fases 2–5: documentar y verificar el daemon, la CLI y sus capacidades antes del launcher.
- Fases 6–7: documentar la UI y su integración con los servicios terminados.
- Fases 8–9: documentar integración Armbian, instalación y resultados de estabilización.
